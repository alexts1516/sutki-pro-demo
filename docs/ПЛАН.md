# План и единый источник правды

Этот файл — короткая карта проекта и список следующих решений. Если работу продолжает другой ИИ (ChatGPT или другой помощник), дайте ему ссылку на репозиторий и на этот файл. Сначала прочитайте этот файл, затем README.md и нужную техническую документацию. Новые решения и изменения сначала добавляйте сюда.

## 1. Что это за проект

Система для владельца посуточных квартир в Астане:

- бренд: **The Address · Apart Hotel**;
- объект: ЖК Highvill, пр. Кошкарбаева 10/1;
- сайт для гостей: просмотр квартир, брони, трансферы и оплата;
- админка владельца и администратора: квартиры, брони, календарь, команда, задачи и финансы;
- приложение команды: водители, мастера и специалисты по подготовке;
- сервер: база данных, вход по ролям, API, уведомления и заготовки интеграций.

Сейчас рядом существуют старое браузерное демо, демо серверной версии v2 и основа настоящего сервера.

## 2. Где что лежит

### Старое демо

Это простой прототип без сервера. Основные страницы и файлы:

- `index.html` — сайт для гостей;
- `app.html` — панель владельца/администратора;
- `cleaning.html` — приложение команды (старое имя осталось в файле);
- `task.html` — задача по одноразовой ссылке;
- `team.html` — вход для команды;
- `login.html` — вход в демо;
- `assets/` — JavaScript, CSS, бренд, переводы, данные и PWA;
- `screenshots/` — снимки экранов.

Также есть `guest.html` и `cleaner.html`: они нужны для старых ссылок и перенаправляют на новые страницы.

### Новое демо v2

Демо серверной версии без настоящего сервера находится в `v2/`:

- `v2/admin/` — админка;
- `v2/app/` — приложение команды;
- `v2/link/` — страница задачи по ссылке;
- `v2/shared/` — общие стили и компоненты;
- `v2/demo/` — браузерная имитация API и базы данных.

Открыть онлайн: <https://alexts1516.github.io/sutki-pro-demo/v2/>.
Данные v2 хранятся только в браузере посетителя.

### Сервер

Папка `server/` — основа настоящего backend на Node.js, Express и Prisma. Техническое описание находится в [`server/README_SERVER.md`](../server/README_SERVER.md).

Быстрый запуск:

```bash
cd server
npm install
npm run setup
npm run dev
```

После запуска админка открывается на `http://localhost:3000/admin/`, проверка сервера — на `http://localhost:3000/api/health`.

### Тесты

В `server/tests/` лежат тесты Node.js. Сейчас их **82**. Запуск: `cd server && npm test`. Также есть проверка на PostgreSQL через `npm run test:pg` при заданном `TEST_DATABASE_URL`.

## 4. Что уже сделано

По `server/README_SERVER.md` уже есть MVP сервера:

- роли и вход для владельца, администратора, водителей, мастеров и специалистов по подготовке;
- админка с квартирами и фото, текстами и брендом сайта, бронями, календарём, командой, трансферами, заявками мастерам, финансами и настройками;
- приложение команды `/app/` и страница одной задачи `/link/<токен>` без входа;
- заявки мастерам: сметы, согласование, выезд, работа, дополнительные расходы, отчёт и фото;
- трансферы: предложения водителям, первый отклик, статусы, уведомления, выплаты и учёт финансов;
- уведомления в Telegram (бот подключается только после добавления токена) и заготовки CloudPayments/PayLink;
- SQLite для разработки, подготовка PostgreSQL для продакшена, локальное или S3-хранилище фото;
- ограничение перебора входа и ссылок, изоляция аккаунтов и 82 автоматические проверки.

Сайт на GitHub Pages к серверу пока не подключён. Реальные платёжные, Telegram, S3 и отслеживание рейсов пока не включены без ключей и договора.

## 5. Бэклог: решения владельца, ещё НЕ внесённые

Ниже — принятые решения и замечания владельца. Эти пункты нельзя считать реализованными, пока они не появятся в коде и тестах.

### Мастер

- После «Начать работу» статус должен стать «В работе».
- Нужна отдельная кнопка «Завершить работу».
- Хранить время начала и окончания.
- Шаг «Я приехал» не обязателен, если смета сделана по фото или без выезда.
- Журнал шагов сделать компактнее.

### Отклонённая смета

- У мастера должны быть два понятных варианта: «Исправить смету» (новая сумма) или «Отказаться от заявки» (заявка возвращается владельцу).
- Это правило нужно для всех мастеров.

### Трансферы

- Использовать только своих водителей владельца, без внешних такси.
- Машину подбирать по числу пассажиров и багажа.
- Вместимость указывать в карточке водителя, класс машины — у гостя.
- Сейчас трансферы делает сам владелец — это основной простой путь.

### Выплаты исполнителям

Исполнители: водители, мастера и специалисты по подготовке.

- Единая система: «К оплате → Выплачено».
- Сразу после завершения работы уведомлять владельца и показывать кнопку «Оплатить».
- Напоминать владельцу, если выплата долго не сделана.
- Исполнитель должен видеть свои выплаты.
- Экран «Долги» нужен как страховка.
- Не допускать недельных задержек.

### Брони и оплата

- Оплата на сайте подтверждает бронь автоматически.
- При «оплате по договорённости» гость регистрируется на сайте, загружает паспорт и билет, описывает ситуацию и получает кнопку связаться в Telegram.
- Владелец проверяет заявку и одобряет её.
- Если владелец не подтвердил заявку и не задал условия оплаты за 24 часа, даты освобождаются.
- Сделать опциональный залог.
- Добавить отметку о ненадёжных гостях.
- Нужна защита от мошенников.

### Названия

Переименовать «уборщица» в «Специалист по подготовке». Короткое название — «Подготовка».

### Чек-лист подготовки

- Редактируемый шаблон владельца.
- Дополнительные пункты для конкретной квартиры.
- Отметки и фото.
- Отметка проблемы → заявка мастеру одной кнопкой.
- В календаре после нажатия «Готово» показывать полный отчёт: кто работал, время начала и конца, чек-лист, фото и проблемы.

### Подключение сайта гостей

Подключить сайт для гостей к серверу: регистрацию, брони и оплату. После подключения проверить весь путь вместе — от регистрации и выбора квартиры до подтверждения брони и оплаты.

### Перед реализацией

Сделать короткий анализ конкурентов:

- Hostaway;
- Guesty;
- Breezeway/Properly — для чек-листов;
- Welcome Pickups — для трансферов.

После этого провести самопроверку за все роли: гость, владелец, администратор, водитель, мастер и специалист по подготовке.

## 6. Что нужно от владельца для запуска

- хостинг;
- домен;
- токен Telegram-бота;
- договор с платёжной системой;
- реальные фото, номера квартир и контакты;
- процент с трансфера.

## Правило для следующих изменений

Сначала прочитать этот файл и `README.md`, затем проверить код, тесты и `server/README_SERVER.md`. Не менять старое демо без отдельной необходимости. Новые функции делать небольшими шагами и добавлять тесты там, где это возможно.
